# SysPulse

Монітор ресурсів macOS, який сам ресурсів не споживає.

## Навіщо

Звичайні монітори показують сухі цифри й самі стають навантаженням: кожне
оновлення запускає `ps` чи `lsof`, а це дорожче за все, що вони міряють.
SysPulse читає дані прямо з ядра і відповідає словами: що зараз не так, хто
винен, що зупинити.

## Ціна роботи (заміри на M4 Pro, 12 ядер, 660 процесів)

| Що | Скільки |
|---|---|
| Фоновий цикл (метрики + усі процеси) | 0.74 мс |
| У фоні, вікно закрите (крок 10 с) | **0.0074% ядра** |
| З відкритим вікном (крок 2 с) | 0.037% ядра |
| Скан портів (лише за кнопкою) | 1.41 мс |
| Памʼять самого додатка | ~86 МБ |

Для порівняння: один запуск `ps -ax` коштує дорожче за двісті наших циклів.

## Головний принцип

**Дешеве — у фоні, дороге — лише за кнопкою.**

- Постійно: метрики ядра, список процесів з памʼяттю і CPU.
- За кнопкою: повторний скан портів, повний перерахунок з розпізнаванням назв.
- Вікно закрите — крок падає з 2 с до 10 с: у menu bar усе одно видно лише
  два числа.

## Що показує

- **Вердикт словами:** «Памʼяті не вистачає: система вивантажує її на диск
  просто зараз» замість голого `swap 91%`.
- **Знахідки:** дублі дев-серверів, завислі процеси, забуті сесії Claude,
  процеси без батька, групи, що зайняли забагато памʼяті.
- **Групи замість списку:** 17 процесів Claude Code — один рядок, що
  розгортається.
- **Порти зі змістом:** «:3000 — Next.js dev», а не `bun *:52924`.
- **Зупинка:** окремого процесу або цілої групи, спершу мʼяким сигналом
  (SIGTERM), щоб процес встиг зберегтись.

Кнопка `i` у шапці розгортає деталі: ядра P і E окремо, склад памʼяті,
час роботи процесів, PID.

## Джерела даних

Жодного зовнішнього процесу. Усе через системні виклики:

| Дані | Виклик |
|---|---|
| CPU по ядрах | `host_processor_info` |
| Памʼять, темп свопінгу | `host_statistics64`, `sysctl vm.swapusage` |
| Черга до процесора | `getloadavg` |
| Процеси | `sysctl KERN_PROC_ALL` + `proc_pidinfo` |
| Назва й джерело процесу | `sysctl KERN_PROCARGS2` |
| Порти | `proc_pidinfo(PROC_PIDLISTFDS)` |

## Перевірено на реальних даних

- Памʼять і своп збігаються з `sysctl` точно.
- RSS процесів збігається з `ps` у 8 випадках з 8.
- Черга до процесора збігається з `uptime`.
- Два штучні дев-сервери на портах 3991 і 3992 розпізналися як дублі
  «Next.js», з памʼяттю й часом роботи; зупинка спрацювала, порти звільнились.

## Обмеження

macOS не віддає деталі системних служб від root (близько 190 процесів із
660) без адмінських прав. Своїх процесів це не стосується. Лічильник у шапці
рахує всі, підказка уточнює, скільки доступно для огляду.

## Збірка

```bash
./build.sh                 # збирає build/SysPulse.app
open build/SysPulse.app
```

Автозапуск при вході вмикається перемикачем у підвалі вікна.
